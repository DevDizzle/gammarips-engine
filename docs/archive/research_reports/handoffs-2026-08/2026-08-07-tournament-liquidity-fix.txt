== WHAT HAPPENED (live evidence, 2026-08-07) ==

Tournament pick GCT (O:GCT260918C00055000, confidence HIGH) emailed at 09:53 ET with
"Liquidity: 2045 prints by ~09:52 (confirmed)". Reality at 10:40 ET:

- Robinhood book: volume 0 for the session, bid 2.65x56 / ask 2.95x15
  (10.7% spread on a 2.80 mark).
- Polygon option snapshot (checked twice, including a force-fresh read): day bar
  frozen at 2026-08-06T16:15 ET with volume 2045. That 2045 is the PRIOR session's
  total volume, not prints today.
- The card's entry $3.20 / limit $3.25 sat ABOVE the live ask (2.95) at 10:40.

  morning (yesterday's sweep became today's OI).

related stale-card defect from 2026-08-06).

== ROOT CAUSE ==

signal-notifier/main.py, _fetch_live_oi (approx L1301-1372):
extracts res.day.volume but never reads res.day.last_updated. The C1 leakage wall
deliberately discards the rest of the day bar. Polygon's v3 option snapshot serves
the PRIOR session's day bar when a contract has no prints yet today, so yesterday's
total volume masquerades as this morning's print count whenever the tape is silent.
This is exactly the failure the print floor was built to catch, inverted into a pass.

Blast radius (all three consumers of the same poisoned number):
1. Print floor (main.py approx L1637-1650): zero-print contracts pass
   PRINT_FLOOR_MIN on phantom prints.
2. Judge input: _candidate_for_ranker (main.py approx L1236-1241) attaches the
   number as early_volume. The tournament prompt's only liquidity directive is
   "prefer the one showing real early trading activity", so all three brackets saw
   GCT as the most-traded name in the pool. Winning rationale led with "massive
   early volume (2045) confirming actionable liquidity".
3. Operator email: _liquidity_email_line (main.py approx L1839) stamps the phantom
   count "(confirmed)".

== FIX 1 (core, one function): date-validate the day bar ==

In _fetch_live_oi:
- Also read res.day.last_updated (nanosecond epoch; see pool_liquidity.py _ns_to_iso
  for the conversion idiom).
- Convert to ET and compare its DATE to the entry day's ET date.
- If the bar date != today (ET): return today_volume = 0 (a KNOWN zero), not the
  stale count.
- Keep today_volume = None ONLY for genuine fetch failures / missing day dict, so
  the C4 fail-open semantics ("fetch failure = no live data, NOT a drop") are
  unchanged. Known-zero and unknown must stay distinct: _known_prints relies on it.
- Leakage note for the decision doc: day.last_updated is a timestamp used solely to
  validate the volume field. No price/greek/IV information crosses the C1 wall. Same
  pre-entry leakage class as the already-permitted live_oi and day.volume reads.

With known-zero flowing, the EXISTING floor (PRINT_FLOOR_MIN=1) drops these names
before the tournament sees them. No new gate. Do not add selection logic elsewhere.

Also update the docstring of _fetch_live_oi (it currently documents the volume read
as "~always 0/None before ~09:52" which is false on stale-bar days: it is
yesterday's total).
